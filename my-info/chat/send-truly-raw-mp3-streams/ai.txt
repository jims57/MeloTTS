Yes, you absolutely can convert variable-length PCM streams into corresponding **raw MP3 streams** (pure MPEG audio frames without ID3 tags, WAV headers, or Xing/VBR headers).

However, because you are dealing with **multiple, variable-length PCM chunks** from a stream, there is a major technical pitfall you must handle to avoid "clicking" or "popping" sounds between the chunks.

Here is the breakdown of how to achieve this cleanly.

---

### 1. The Core Concept: What is a "Raw" MP3?

Unlike WAV files, which require a header to define sample rate and bit depth, MP3 is a **frame-based format**.

* **Structure:** An MP3 stream is just a sequence of frames.
* **Self-Describing:** Each frame starts with a "Sync Word" (usually `0xFFF`) and a header that tells the decoder the bitrate and sample rate for *that specific frame*.

**This means:** You can technically strip all file-level metadata (ID3, Xing) and just concatenate MP3 frames back-to-back, and a player will play them.

### 2. The Critical Challenge: The "Bit Reservoir" & Padding

This is the most important part of your implementation.

If you treat every PCM chunk as an isolated file, encode it, and then try to join the MP3s later, you will hear audio glitches.

* **The Issue:** MP3 encoders (like LAME) use a "bit reservoir." Data from the end of one frame often spills over into the start of the next to improve compression.
* **The Glitch:** If you close the encoder after every chunk, the encoder will "flush" the stream, inserting **silence/padding** at the end to finish the last frame.
* **The Result:** When you stick those MP3s together, you get: `[Audio A] [Silence] [Audio B] [Silence]`.

### 3. The Solution: Streaming Encoding

To get a truly raw, seamless MP3 stream, you must keep the **Encoder State** open. You cannot initialize a new encoder for every PCM chunk.

#### The Architecture

1. **Initialize Encoder:** Start the encoder instance *once* (set to "Raw" mode, no headers).
2. **Loop:** Receive PCM Chunk  Feed to Encoder  Receive specific MP3 Frames.
3. **End:** Only when the TTS session is totally finished do you send the "Flush" command to the encoder.

---

### 4. Implementation (Python & FFmpeg example)

The most robust way to do this without writing complex C code is to use **FFmpeg** via a pipe. FFmpeg wraps the LAME encoder and allows us to strictly disable headers.

**The Goal:**

* Input: `s16le` (Signed 16-bit Little Endian PCM)
* Output: `mp3` (Raw format)
* Flags: `write_xing 0` (No Xing header), `id3v2_version 0` (No ID3 tags).

Here is a Python script demonstrating how to simulate a stream of PCM chunks and convert them into a clean, raw MP3 stream.

```python
import subprocess
import numpy as np

# Configuration for the input PCM (Must match your TTS API output)
SAMPLE_RATE = 24000 
CHANNELS = 1
BYTES_PER_SAMPLE = 2  # 16-bit audio

def create_ffmpeg_pipe():
    """
    Opens a persistent FFmpeg process that reads raw PCM from stdin
    and writes raw MP3 frames to stdout.
    """
    command = [
        'ffmpeg',
        '-y',                  # Overwrite output
        '-f', 's16le',         # Input format: Signed 16-bit Little Endian
        '-ac', str(CHANNELS),  # Input Channels
        '-ar', str(SAMPLE_RATE), # Input Sample Rate
        '-i', 'pipe:0',        # Read from Standard Input (stdin)
        
        # OUTPUT SETTINGS
        '-f', 'mp3',           # Output format: MP3
        '-write_xing', '0',    # CRITICAL: Do not write Xing/VBR header
        '-id3v2_version', '0', # CRITICAL: Do not write ID3 tags
        'pipe:1'               # Write to Standard Output (stdout)
    ]
    
    # Open the process
    process = subprocess.Popen(
        command,
        stdin=subprocess.PIPE,
        stdout=subprocess.PIPE,
        stderr=subprocess.DEVNULL # Hide FFmpeg logs (optional)
    )
    return process

def process_tts_stream():
    encoder = create_ffmpeg_pipe()
    
    # Simulate receiving 3 chunks of PCM data from TTS
    # In reality, you would be looping over your API response
    chunks = [np.random.bytes(1024) for _ in range(5)] # Dummy PCM data

    try:
        print("--- Starting Stream Encoding ---")
        
        for i, pcm_chunk in enumerate(chunks):
            # 1. Write PCM chunk to FFmpeg's stdin
            encoder.stdin.write(pcm_chunk)
            
            # 2. Flush stdin ensures FFmpeg gets the data immediately
            encoder.stdin.flush()
            
            # 3. Read available MP3 data from stdout
            # Note: In a real async stream, you'd read non-blocking.
            # Here we read a fixed buffer or available bytes.
            # FFmpeg buffers internally, so you might not get data back 
            # *immediately* after every write, which is fine.
            raw_mp3_data = encoder.stdout.read(1024) 
            
            if raw_mp3_data:
                # This 'raw_mp3_data' is PURE mp3 frames. 
                # Send this to your client/storage.
                print(f"Chunk {i}: Encoded {len(raw_mp3_data)} bytes of MP3")

        # 4. End of Stream: Close stdin to tell FFmpeg "EOF"
        encoder.stdin.close()
        
        # 5. Read the final remaining frames (the flushed buffer)
        remaining_data = encoder.stdout.read()
        if remaining_data:
            print(f"Final Flush: Encoded {len(remaining_data)} bytes of MP3")
            
    except Exception as e:
        print(f"Error: {e}")
    finally:
        encoder.wait()

if __name__ == "__main__":
    process_tts_stream()

```

### 5. Summary of Technical Requirements

To ensure the output is exactly what you requested:

| Feature | Flag/Setting | Reason |
| --- | --- | --- |
| **No File Header** | `-f mp3` (not `-f wav`) | Ensures we aren't wrapping it in a RIFF container. |
| **No ID3 Tags** | `-id3v2_version 0` | Prevents metadata tags at the start. |
| **No VBR Header** | `-write_xing 0` | Prevents the "Xing" or "Info" header used for VBR seeking. |
| **Seamless Audio** | **Single Process** | You must feed all PCM chunks into **one** encoder instance. Do not restart the encoder for each chunk. |
